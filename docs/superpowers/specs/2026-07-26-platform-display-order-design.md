# プラットフォーム表示順の一元化と並べ替え UI（v2.5.0）

- 日付: 2026-07-26
- ステータス: 設計合意済み
- 対象バージョン: v2.5.0（MINOR）

## 1. 背景と問題

商品カードの CTA 行（`<li class="affilicard-card__row">`）は、`CardRenderer::renderListings()` が
`visibleListings()` の戻り配列を**そのままの順序**で描画している。この配列順は商品メタ
`affilicard_listings` の**登録順**そのものである。

一方 `PlatformDefinition` には `displayOrder` があり、プラットフォーム設定 UI にも
「表示順」という数値入力が存在するが、**CTA 行の並びには一切効いていない**。
`displayOrder` の唯一の実利用箇所は `CardRenderer::selectCardImage()` の
「`imagePriority` 同値時のタイブレーク」だけである。

### 実際に起きる不具合

listing を後から追記する運用（記事生成時点では取得できなかったストアの listing を、
後追いで REST 経由でメタに merge する等）では、追記された listing が配列末尾に付く。
その結果、**同じ記事の中でカードごとにボタンの並びが食い違う**。

例（電子書籍カード 6 枚のうち 1 枚だけ順序が逆転する）:

- カード 1〜2: ストアB → ストアA
- カード 3: **ストアA → ストアB**（この 1 枚だけ逆）
- カード 4〜6: ストアB → ストアA

読者から見ると同一記事内でボタン位置が動くため、比較しづらく誤クリックも誘発する。

### 設定 UI 側の問題

- 「表示順」は各プラットフォームのアコーディオンを開かないと見えず、**全体の並びが一覧できない**。
- 数値の手入力なので、値の重複・欠番が容易に起き、直感的に並べ替えられない。
- そもそも「この数字が何の順番なのか」が画面から読み取れない。

## 2. 設計方針

**表示順の SSOT をプラットフォーム設定（`displayOrder`）に一本化する。**

1. **レンダラー**: `visibleListings()` の戻りを `displayOrder` 昇順で安定ソートしてから返す。
   listing の登録順は表示順に影響しなくなる。
2. **管理 UI**: プラットフォーム設定の各商品タイプタブで、行ごとに順位バッジと ↑ / ↓ を持たせ、
   アニメーション付きで並べ替える。保存時に `displayOrder` を 1..N の連番で振り直す。
   既存の「表示順」数値入力は撤去し、入力口を ↑ / ↓ に一本化する。
3. **説明文言**: 「何の順番か」「無効なプラットフォームはどう扱われるか」「いつ反映されるか」を
   タブ先頭に明示する。

利用サイト側（listing を書き込む外部スクリプト等）の変更は不要。プラグイン側で描画順を決めるため、
**公開済み記事も再投稿なしで是正される**。

## 3. レンダラーの変更

対象: `src/Renderer/CardRenderer.php`

`visibleListings()` の末尾で安定ソートを行う。

- ソートキー: `$by_code[$listing['platform']]->displayOrder`（昇順）
- 同値のタイブレーク: **元の出現順**（配列 index）。PHP の `usort` は安定ソートだが、
  意図を明示するため index を明示的に第 2 キーとして比較する。
- 未知 code / 無効 platform は既に同メソッド内で除外済みのため、`$by_code` の欠損は考慮不要。

### 影響範囲

| 呼び出し元 | 影響 |
| ---------- | ---- |
| `renderListings()` | **CTA 行が `displayOrder` 順になる**（本変更の目的） |
| `renderTimestamp()` | 最新 `last_verified_at` を取るだけなので順序非依存＝結果不変 |
| `selectCardImage()` | **並びの先頭から `image_url` 非空の最初の 1 件を採る**（下記「書影の選択も表示順に従わせる」） |

### 明示的に採用しない選択肢

- **ブロック属性 `onlyPlatforms` の指定順を並びに反映する**: 採用しない。
  表示順の決定点が「設定」と「ブロック属性」の 2 箇所に分かれ、SSOT が壊れる。
  `onlyPlatforms` は今後も**許可リスト（フィルタ）**であり、順序の意味を持たない。
- **listing 側に順序フィールドを持たせる**: 採用しない。商品ごとに順序を持つと、
  サイト全体でボタン位置を揃えるという目的に反する。

### 書影の選択も表示順に従わせる

商品カードのサムネイル（書影）は `selectCardImage()` が選ぶ。従来は `PlatformDefinition::imagePriority`
（小さいほど優先）を主キー、`displayOrder` を同値時のタイブレークとしていた。

本設計では**書影も表示順に従わせる**。`visibleListings()` は既に `displayOrder` 昇順なので、
その並びを頭から走査して `image_url` が非空の**最初の listing** の画像を採る。

これにより `imagePriority` は役目を失うため**撤去する**。設定として存在するのに何も効かない値は、
本設計が解消しようとしている問題（`displayOrder` が UI にあるのに描画に効いていなかった）と
同じ形であり、残す方が有害である。

撤去する範囲:

- `PlatformDefinition` のコンストラクタ引数・public readonly プロパティ・`toArray()` の出力キー・
  `fromArray()` の読み取り
- `PlatformConfig::defaults()` の `imagePriority: 10 / 20 / 30`
- プラットフォーム設定 UI の「画像優先度（小さいほど優先）」数値入力
- 上記に紐づくテスト

既存インストールの `affilicard_platforms` オプションには `imagePriority` キーが残るが、
`fromArray()` が読まなくなるため無視される。次回の保存で `toArray()` の出力から消える。
マイグレーションは不要。

「ボタンは DMM を先頭にしつつ、書影は別ストアの高画質なものを使う」という使い分けはできなくなる。
表示順という 1 つの概念に統合することを優先する。

### 既存表示との差分

デフォルトの `displayOrder` は DMM ブックス=1 / Amazon Kindle=2 / 楽天Kobo=3 である。
本変更後、電子書籍カードの CTA は**この順に統一される**。現行で多数派になっている並びと
異なる結果になる場合があるが、それは登録順に依存した偶然の並びであり、
希望する並びは新しい並べ替え UI で設定する。

## 4. 管理 UI の変更

対象: `src/Admin/components/PlatformsPanel.jsx` / `src/Admin/components/PlatformEditor.jsx`

### 4-1. レイアウト

既存の「プラットフォーム設定 → 電子書籍 / VOD / API 認証」タブ構成は維持する。
各タブのプラットフォーム行の左側に、順位バッジと ↑ / ↓ を置く。

```text
プラットフォーム設定
┌───────┬──────┬────────┐
│電子書籍 │ VOD  │ API 認証 │
└───────┴──────┴────────┘

 この順番で商品カードのボタンが上から並びます。
 ・無効なプラットフォームはカードに表示されないため、この順番には含まれません。
 ・順番が意味を持つのはタブ（商品タイプ）の中だけです。
 ・「保存」を押すと、公開済みの記事のカードにも反映されます。

 ┌───┬───┐
 │ 1 │ ↑ │  DMMブックス (dmm-books)                        ▾
 │   │ ↓ │
 ├───┼───┤
 │ 2 │ ↑ │  Amazon Kindle (amazon-kindle)                  ▾
 │   │ ↓ │
 ├───┼───┤
 │ 3 │ ↑ │  楽天Kobo (rakuten-kobo)                        ▾
 │   │ ↓ │
 ├───┼───┤
 │ — │   │  BookWalker (bookwalker) — 無効       （淡色）   ▾
 └───┴───┘
                                              [ 保存 ]
```

- ↑ / ↓ は `PanelBody` の**外側**に置く。`PanelBody` の `title` はボタン要素として描画されるため、
  その中に操作ボタンを入れると入れ子のインタラクティブ要素になり不正な DOM になる。
  行を flex コンテナでラップし、左に順序コントロール・右に既存の `PlatformEditor` を配置する。
- 順位バッジは**有効なプラットフォームにだけ**、そのタブ内での 1 始まりの連番を振る。
  無効行はバッジを `—` とし、↑ / ↓ を描画しない（淡色表示）。
  バッジは「カード上で何番目に出るか」を表すため、`displayOrder` の値そのものではない
  （無効行や他タイプの行を飛ばして数える）。
- 先頭の有効行の ↑、末尾の有効行の ↓ は `disabled`。

### 4-2. 並べ替えの意味論

- ↑ / ↓ は「**同じタブ内の、1 つ前 / 後の有効なプラットフォーム**」と位置を入れ替える。
  無効行や他タイプの行は読み飛ばす。
- 入れ替えは `platforms` 配列（グローバル）の**位置の交換**で行う。2 要素の位置交換なので、
  その間に挟まる無効行・他タイプ行の位置は変わらない。
- 交換後、配列全体の `displayOrder` を**配列 index + 1 で振り直す**（1..N の連番）。
  これにより既存データの重複値・欠番が正規化され、サーバ側の `PlatformConfig::save()` による
  `displayOrder` 昇順の再ソートが UI 上の並びと一致する。
- 無効なプラットフォームも連番の対象に含める。並べ替え対象から外すだけで、
  配列上の位置＝相対順は保持されるため、再有効化すれば元の位置に戻る。

`displayOrder` の連番付与は**クライアント側**で行い、既存の `PUT /affilicard/v1/platforms` に
そのまま送る。サーバ（`PlatformsSettings::update()` / `PlatformConfig::save()`）は変更しない。
サーバ側で振り直すと、タブによる型フィルタと並べ替えの関係をサーバが再現する必要があり、
クライアントが既に保持している情報を二重に持つことになるため。

### 4-3. 並べ替えアニメーション

↑ / ↓ 押下時、行が実際に上下へ滑って入れ替わるアニメーションを伴う。

- 手法は **FLIP**（First-Last-Invert-Play）。アコーディオンの開閉で行の高さが変わるため、
  固定高を前提とした CSS transition では破綻する。FLIP なら任意の高さで成立する。
  1. 押下直前に各行の `getBoundingClientRect().top` を記録（First）
  2. state を更新して再描画（Last）
  3. `useLayoutEffect` で新しい位置を測り、差分を `transform: translateY(Δ)` として当てる（Invert）
  4. Web Animations API（`element.animate()`）で `translateY(0)` までアニメートする（Play）
- 対象は**そのタブに表示されている全行**。入れ替わる 2 行だけでなく、
  高さの違いで押し出される行も自然に動く。
- 時間 180ms、イージング `ease-in-out`。
- `window.matchMedia('(prefers-reduced-motion: reduce)')` が真ならアニメーションを行わず即座に反映する。
- `element.animate` が存在しない環境（jsdom を含む）ではアニメーションをスキップし、
  並べ替え自体は必ず成立させる。アニメーションは**装飾であり、機能の前提にしない**。
- React の再描画で要素が使い回されるよう `key` は `platform.code` を使う（既存実装のまま）。

### 4-4. アクセシビリティ

- ↑ / ↓ には `aria-label` を付ける（例: 「DMMブックスを上へ移動」「DMMブックスを下へ移動」）。
  アイコンのみのボタンで、ラベルが無いと読み上げが「ボタン」になるため。
- 並べ替え後の結果を `aria-live="polite"` の領域で通知する
  （例: 「DMMブックスを 2 番目に移動しました」）。
- 移動によってフォーカス中のボタンが `disabled` になった場合（端に到達した場合）、
  フォーカスが body に落ちてキーボード操作が途切れる。同じ行のもう一方のボタンへフォーカスを移す。

### 4-5. 撤去するもの

- `PlatformEditor` 内の「表示順」`TextControl` を削除する。
  ↑ / ↓ と数値入力の 2 系統が残ると、値が食い違ったときに並びが壊れるため。
- 「画像優先度（小さいほど優先）」の数値入力も撤去する。書影の選択を表示順に統合するため
  （§3「書影の選択も表示順に従わせる」）。

## 5. テスト

### 5-1. PHP（PHPUnit）

`tests/Unit/Renderer/CardRendererTest.php` に追加する。

| ケース | 期待 |
| ------ | ---- |
| listing の登録順が `displayOrder` と逆 | CTA 行が `displayOrder` 昇順で出力される |
| `displayOrder` が同値の 2 件 | 登録順が保たれる（安定ソート） |
| 無効 platform を含む | 従来どおり除外され、残りが `displayOrder` 順 |
| `only_platforms` の指定順が `displayOrder` と逆 | `displayOrder` 順で出力される（指定順は無視） |
| 書影選択 | 並びの先頭から `image_url` 非空の最初の 1 件が選ばれる |
| 先頭 listing に `image_url` が無い | 次の listing の画像へフォールバックする |
| どの listing にも `image_url` が無い | WP アイキャッチ（`options['image_url']`）へフォールバックする |
| `toArray()` / `fromArray()` | `imagePriority` キーを持たない。既存データに残っていても無視する |

### 5-2. JS（Vitest + Testing Library）

`tests/js/components/PlatformsPanel.test.jsx` に追加する。

| ケース | 期待 |
| ------ | ---- |
| ↓ を押す | 同タブ内の次の有効行と表示順が入れ替わる |
| ↑ を押す | 同タブ内の前の有効行と表示順が入れ替わる |
| 間に無効行が挟まる | 無効行を読み飛ばして有効行同士が入れ替わり、無効行の位置は動かない |
| 先頭行の ↑ / 末尾行の ↓ | `disabled` |
| 無効行 | ↑ / ↓ が存在せず、順位バッジが数字でない |
| 保存 | PUT の payload の `displayOrder` が配列順どおりの 1..N 連番 |
| `aria-label` | 各ボタンにプラットフォーム名を含むラベルがある |

`tests/js/components/PlatformEditor.test.jsx` から「表示順」入力に関するテストを削除する。

アニメーションは jsdom で位置を測れないため単体テストの対象外とし、
「`element.animate` が無い環境でも並べ替えが成立すること」だけを担保する。

### 5-3. E2E（Playwright）

`tests/e2e/` に 1 本追加する。

1. `displayOrder` と逆順の listing を持つ商品を seed する
2. 記事を表示し、CTA の並びが `displayOrder` 順であることを確認する
3. 管理画面で ↑ / ↓ を押して保存する
4. 記事を再読み込みし、CTA の並びが変わっていることを確認する

これにより「設定 → 保存 → 公開画面への反映」が通しで検証される。

## 6. バージョンと互換性

- **v3.0.0（MAJOR）**。`imagePriority` の撤去により、`PlatformDefinition` の public な
  コンストラクタ引数・プロパティと `GET/PUT /affilicard/v1/platforms` のペイロードから
  キーが 1 つ消える。これは公開 IF の破壊にあたる。
  `displayOrder` 自体のキー名・型・REST の形は不変。
- リリース時は `affilicard.php` の `Version:` ヘッダと `package.json` の `version` を
  同一コミットで揃える（更新チェッカがタグのツリーのヘッダを読むため）。
- 既存インストールの `displayOrder` 値はそのまま使われる。マイグレーションは不要。
  初回に並べ替えて保存した時点で 1..N に正規化される。

## 7. スコープ外

- カード CTA のミニプレビューを管理画面に出すこと。まず 4-1 の説明文言で足りるかを見る。
- ドラッグ&ドロップによる並べ替え。↑ / ↓ で目的を満たすため、依存を増やしてまで入れない。
- カード書影を「表示順の先頭」以外の規則で選ぶ手段の再提供（`imagePriority` の代替）。
  必要になったら別途設計する。
- listing を書き込む外部スクリプト側の並び順。プラグイン側で描画順を決めるため不要。
